# AGENTS.md

YealinkNotifier is a **cross-platform (Windows / Linux / macOS), small Go app**: an HTTP server that receives Yealink phone "Incoming Call" webhooks and shows a **system notification + beep**, with a **system-tray icon** (status toggle, per-channel toggles, in-memory call history + Exit for graceful shutdown). Runtime parameters come from an optional **YAML config file**, with **CLI flags as overrides** and hardcoded defaults as the last resort. Go 1.27, module `YealinkNotifier`.

## Layout

- `main.go` — flags, config resolution (via `config`), `log` setup, the startup banner (includes the resolved config-file and contacts-file lines), the composition root (wires `config` + `contacts` + `core` + `server` + `tray`), the SIGINT/SIGTERM watcher, and the bounded (~5s) shutdown closure.
- `config/` — leaf package: resolves `port`/`addr`/`notify`/`beep`/`allowed_ips`/`logfile`/`quiet`/`contacts` from the optional YAML file + CLI overrides + defaults. Exports `Effective`, `Flags` (values + per-flag `Set*` presence), `Load(configPath, Flags)`, `Default*` consts, `DefaultLogfile()`. Unexported: `file` (pointer-view, "key absent" ≠ "zero value"), strict two-pass decode into a key/node map (exact `config error: ...` text — E1 unparseable / E2 unknown key / E3 wrong type, sorted-key deterministic), search candidates (exec-dir → CWD → `os.UserConfigDir()`), and `merge` (flag → file → default). Imports only stdlib + `gopkg.in/yaml.v3`; performs no logging, never creates or writes any file. For `contacts` it only carries the string through precedence — all search/resolve/create logic lives in `contacts`.
- `contacts/` — leaf package (stdlib only, no cgo): the local contacts book (CSV `number,name`). `Resolve(configured)` (never errors, never creates — read-only `os.Stat` probing; explicit path → absolute; else first existing regular `contacts.csv` among exec-dir → CWD → `os.UserConfigDir()`; none found → creation target CWD → user-config-dir → exe-dir, each fallback only when the previous base dir cannot be *determined*), `New(path)` (no I/O), `Book.Path/Lookup/Display/Version/EnsureFile/Open`. Per-call re-read via an mtime/size cache under one mutex (`refresh`); `Version` increments on every observed file change (incl. deletion and parse-failure degradation) and doubles as the tray's refresh tick. **Fail-open**: a missing or malformed file → warn + no names; an unreadable file → warn + keep the last-good names (no names only if it never loaded); never a startup error. Names are sanitized at the single `parse` choke point (control chars folded to single spaces, XML-unsafe `< > & " '` stripped, 64-rune cap — same hygiene as `core.sanitizeCaller`, because beeep's Windows toast path interpolates the body into unescaped CDATA + a PowerShell here-string); numbers stay raw exact-match keys. Nil `*Book` is valid (`Path` "", `Lookup` "", `Display` unchanged, `Version` 0, `EnsureFile`/`Open` error). `EnsureFile` creates file + parent dirs idempotently (UTF-8 BOM + `number,name\r\n` header, `O_CREATE|O_EXCL`, never truncates an existing file; least privilege 0o600 file / 0o700 dirs; a failed write removes the partial stub). `open_windows.go`/`open_linux.go`/`open_darwin.go`/`open_other.go` — the per-OS default-app opener (`rundll32 url.dll,FileProtocolHandler` / `xdg-open` / `open` / unsupported error).
- `core/` — `App`: two independent channel states (`notify` / `beep`, each `atomic.Bool`; constructor `New(notify, beep)`), `OnCall` (sanitizes the caller, records the event **even if both channels are off**, then dispatches `Notify` and/or `Beep` per enabled channel, each in its own goroutine), `Notify`/`Beep` via `beeep`, and the shutdown orchestration (`Shutdown` is `sync.Once`-deduped, `Done()` closes after the server drain). Additive `SetContacts(*contacts.Book)` (must be called before the server starts) + `Contacts()` accessor; the name lookup happens inside the notify goroutine via the unexported `callerMessage` helper — no disk I/O on the HTTP handler path. `history.go` — the in-memory call history: `RecordEvent`/`Events` (defensive copy, newest first)/`ClearHistory`/`HistoryVersion`, `HistoryCapacity` = 20 (memory only, no persistence; stores **raw sanitized numbers only**, never names). `beep_windows.go`/`beep_other.go` — beep fallback on Windows (`MessageBeep` when `beeep.Beep` fails) / passthrough log on other OSes.
- `server/` — the `http.Server` (full timeout set) + the method-agnostic `/` handler (query `number` with `caller` fallback; optional IP allow-list — `New` returns an error on any unparseable entry, the handler checks `r.RemoteAddr` and answers `403 Forbidden`) + bounded `Shutdown`.
- `tray/` — the `systray` menu (top→bottom): master "Disable/Enable notifications" toggle, "Show notifications" checkbox, "Play sound" checkbox, separator, **History** submenu (last 20, newest first; 20 pre-created slot items — stable IDs, no add/remove — shown/hidden per occupancy: `SetTitle` + `Show()` when used, `Hide()` when unused; Windows appends reshown items in call order → keep ascending index iteration), "Clear history", "Edit contacts" (ensures the CSV exists, then opens it in the OS default app), separator, Exit; plus `Stop()`, the headless-safe `RunSafe` wrapper, and the per-OS `trayIconBytes` selector (ICO on Windows, PNG on Linux/macOS). The tray reaches the contacts book via `app.Contacts()` (it does **not** import `contacts`); history labels use `Book.Display`, and the render loop re-renders on `Book.Version()` changes too.
- `images/` — embedded icons: PNG (`PngOnData` green / `PngOffData` red / `PngIncomingData` for `beeep.Notify`) for the Linux/macOS tray + notifications, ICO (`IcoOnData`/`IcoOffData`) for the Windows tray.
- **Test suite (real now):** `core/app_test.go` (caller sanitization), `core/history_test.go` (capacity, ordering, versioning, concurrency), `core/toggles_test.go` (channel toggles; `OnCall` records with zero side effects), `core/contacts_test.go` (`callerMessage` incl. CDATA-safe bodies, raw-number recording with a book), `contacts/contacts_test.go` (parse incl. name sanitization, resolve, mtime/size cache, `EnsureFile`, concurrency), `server/server_test.go` (allow-list parsing/matching, handler accept/deny), `config/config_test.go` (schema/defaults, empty-file cases, per-OS resolution via `t.TempDir`/`t.Setenv`/`t.Chdir`, precedence matrix, exact E1–E9 error text). Hermetic — no network, no real notifications.
- A small set of packages (`main`, `config`, `core`, `server`, `tray`, `contacts`, `images`) with a one-way dependency graph `main → {config, core, server, tray, contacts}` and `core → contacts`; `config` is a leaf (stdlib + `gopkg.in/yaml.v3` only), `contacts` is a leaf (stdlib only). No frameworks, no further abstraction layers. Keep it that way.

## Commands

- Run: `make run` (=`go run .`) or the built binary. Runtime parameters are resolved **per parameter, highest first: explicit CLI flag > YAML config file > hardcoded default** (flag = presence on the command line via `flag.Visit`, so a flag set to its default value still wins). Flags: `-config` (path to a YAML config file; empty = auto-discover `config.yml` next to the executable → in the CWD → in `os.UserConfigDir()`; a missing *explicit* file = startup error; none found in search mode = defaults + WARN), `-port` (default `8080`), `-addr` (default `0.0.0.0`), `-logfile` (default: a file under the OS user-cache dir; empty string = console), `-quiet` (disable logging), `-notify` (default `true` — system-notification channel), `-beep` (default `true` — sound channel), `-allowed-ips` (default empty = allow all; comma-separated client IPs / CIDRs; **any** unparseable entry = startup error, exit 1, before the socket opens), `-contacts` (default empty = auto-discover `contacts.csv` next to the executable → in the CWD → in `os.UserConfigDir()`; an explicit path is used as-is; an explicit empty `-contacts=` beats the YAML key and re-enables auto-discovery; the contacts file is fail-open — never a startup error), `-version` (print version and exit). The YAML file mirrors the same keys in snake_case: `port`, `addr`, `notify`, `beep`, `allowed_ips`, `logfile`, `quiet`, `contacts` — all optional.
- Verify: `make test` (`go test ./...`) — the repo **has a test suite** covering `config` (schema / resolution / precedence / error text), `contacts` (parse / resolve / cache / `EnsureFile` / concurrency), `core` (sanitize / history / toggles / `callerMessage` + raw-number recording) and `server` (allow-list); hermetic, no network. Plus `make vet` (`go vet ./...`) and a format check — `gofmt -l .` (lists files needing formatting; empty = clean) or `make fmt` (auto-fixes). Run `make test` and `make vet` before declaring a change done.
- Build: `make build` (native) → `bin/YealinkNotifier`; cross-builds `make build-windows` / `make build-linux` / `make build-darwin` → `dist/`. All builds are **`CGO_ENABLED=1`** (see gotchas). Built with `-trimpath -ldflags "-s -w -X main.version=$(VERSION)"`. Binaries in `bin/`/`dist/` are gitignored and pre-existing — never commit or delete them.

## Conventions (do NOT change)

- **Cross-platform is the point.** Do **not** reintroduce platform-specific paths in shared code (`winmm.dll`/`PlaySoundW`, PowerShell, `go-toast`). Notifications+sound go through `github.com/gen2brain/beeep`; the tray goes through `github.com/getlantern/systray`. The **only** sanctioned platform exceptions are the three build-tagged spots: `core/beep_windows.go` (Windows `MessageBeep` fallback via `syscall`, see gotchas), `trayIconBytes` in `tray/tray.go` (ICO vs PNG selection), and `contacts/open_windows.go`/`open_linux.go`/`open_darwin.go`/`open_other.go` (the per-OS default-app opener). Add new cross-platform behavior without breaking the win/linux/darwin builds.
- **Tray semantics:** icon = channel state — **green** (per-OS `IcoOnData`/`PngOnData`) when *at least one* channel is on, **red** (`IcoOffData`/`PngOffData`) when both are off; tooltip `YealinkNotifier — notifications ON/OFF`. Menu order (top→bottom): master toggle (click = both channels on → both off, otherwise → both on), "Show notifications" (channel checkbox), "Play sound" (channel checkbox), separator, **History** submenu (last 20, newest first, `HH:MM:SS — <caller>`; 20 pre-created slot items — stable IDs, created once in `onReady` — **shown/hidden per occupancy**: `SetTitle` + `Show()` when occupied, `Hide()` when unused; do **not** switch to lazy creation or dynamic add/remove, systray v1.2.2 has no item-removal API; on Windows re-added items are appended in `Show()` call order → iterate slots in **ascending** index order), "Clear history", "Edit contacts", separator, **Exit**. When all channels are OFF the server must still answer `200 OK` (allowed clients); only the toast/beep are suppressed.
- **Independent channels:** `-notify` / `-beep` are independent (both default `true`) and map to `core.New(notify, beep)`; `OnCall` dispatches `Notify` and/or `Beep` per enabled channel, each in its own goroutine, and records the event *first* — even when both channels are off. Rejected (403) requests are **not** recorded. Preserve this.
- **YAML config:** the eight runtime parameters resolve per parameter, highest first — **explicit CLI flag > YAML value > hardcoded default**. "Explicit" = the flag is *present* on the command line (`flag.Visit`), so `-port=8080` (the default value) still overrides the file. Config file: `-config <path>` (missing file = startup error, exit 1, no socket — an explicit miss is never skipped past), or in search mode `config.yml` next to the executable → in the CWD → in `os.UserConfigDir()`, first existing regular file wins, none found = defaults + a WARN on stderr. The file is **read-only** — the app never creates, modifies, or deletes it — and is read **once at startup** (no hot-reload). Decoding is strict: unparseable YAML, an **unknown key**, or a **wrong-typed key** are all startup errors (exit 1, before the socket opens); an empty/whitespace-only/`{}` file is valid and yields all defaults. Config errors and the no-config WARN go to **raw stderr** (the sink is itself a config product, so `main` writes them via `fmt.Fprintln(os.Stderr)` before `setupLogging` — keep them out of the `log` package, so a `quiet: true` in the file can never hide a startup failure). `allowed_ips` entries — YAML or flag — still flow through the existing `server.New` → `parseAllowedIPs` fail-closed choke point.
- **`config` package is a leaf:** stdlib + `gopkg.in/yaml.v3` only, no other app package, no logging, no file/dir creation or writing, no cgo. Keep it pure and keep precedence logic in it; `core`/`server` signatures and the one-way graph stay untouched by it.
- **Contacts book is a fail-open convenience:** the `-contacts` flag / YAML `contacts` key (flag wins; an explicit empty `-contacts=` re-enables auto-discovery) only carries a path string through `config` — all search/resolve/create logic lives in the `contacts` leaf package. A missing or malformed CSV → a WARN log + no names; an unreadable CSV → a WARN log + the last-good names kept (no names only if it never loaded) — **never** a startup error (unlike the config file and the allow-list). The file is re-read per call via an mtime/size cache (one `os.Stat` per lookup; reload only on a signature change), so edits apply without restart. Names are sanitized at the single `parse` choke point (control chars folded to single spaces, XML-unsafe chars stripped, 64-rune cap — the notification body must stay safe for beeep's Windows CDATA/PowerShell here-string path); numbers are exact-match keys and stay raw. The history stores **raw sanitized numbers only** — names are decoration applied at display time (`Book.Display` in the tray, `callerMessage` in the notify goroutine). The contacts CSV is the **only** persistence in the app; the call history stays memory-only. When auto-discovery finds nothing, "Edit contacts" creates the file in the CWD, falling back to the user config dir then the exe dir only when a base dir cannot be *determined* (see gotchas). Excel users should save as **"CSV UTF-8"** — a UTF-8 BOM is tolerated/stripped, invalid UTF-8 is malformed.
- **IP allow-list:** the `-allowed-ips` flag or the YAML `allowed_ips` list (flag wins) with default empty = allow all restricts the webhook by **TCP peer address only** (`r.RemoteAddr` — no `X-Forwarded-For`; behind a proxy the client appears as the proxy's IP). Empty/whitespace entries are skipped; **any** unparseable entry = startup error, exit 1, *before the socket opens* (fail-closed); when set, the startup banner logs the entry count. Denied requests → `403 Forbidden`, body `Forbidden`, logged. Keep it in the server package.
- **Graceful shutdown:** `Exit` / SIGINT / SIGTERM must end the tray loop, drain the HTTP server (bounded, ~5s), and only then let the process exit — the wait is enforced by `tray.RunSafe` blocking on `app.Done()`. `systray.Quit()` is only ever called from background goroutines (signal watcher, Exit item) — **never from the `systray` event-loop (`onExit`)**, because on macOS `systray.Quit()` blocks until the run loop finishes terminating (that is what fires `onExit`), so calling it there deadlocks.
- The tray code must be **headless-safe**: if the tray can't start (no display / no DBUS), recover and continue as a notification-only server rather than crashing.
- **Icons:** the embedded icons in `images/` are the single source. **Windows tray** must use the ICO bytes (`IcoOnData`/`IcoOffData`) — systray's Win32 `LoadImage` only reads `.ico` files (PNG fails silently with the bogus "The operation completed successfully."); **Linux/macOS tray** use the PNG bytes; **`beeep.Notify`** keeps the PNG bytes (the `PngIncomingData` icon; the Windows tray is the only ICO consumer.). Select per-OS via the `trayIconBytes` helper in `tray/tray.go`. Do not add icon tooling.
- User-facing strings, tray labels, and log messages are **English** — keep new strings in English. User-facing (non-log) text is the notification `Incoming call from Yealink` / `Caller: %s (%s)` (known contact) / `Caller number: %s` (fallback when no caller: `You are being called! Check your office phone.`) — preserve it.
- Webhook contract: handle **any HTTP method** on `/`; read query `number` (Yealink sends `$remote_number`), falling back to `caller`; respond `200 OK` with body `OK` (`403 Forbidden` when the allow-list denies). The caller value is sanitized (SIP URI reduced to the number, trailing `_<suffix>` stripped, XML-unsafe chars removed, length capped) before it is used in the notification or recorded in the history — preserve this. Keep it minimal: no auth, no call persistence — the call history is intentionally in-memory only (capacity 20, lost on restart); do **not** add disk/network persistence for it (the user-edited contacts CSV is the only file the app may create).
- Code comments are in English; match local style.

## Logging

- Route all runtime output through the standard `log` package (never `fmt.Println` for operational messages). The startup banner (the resolved `Config file:` and `Contacts file:` lines, and the allowed-entry count when set), webhook events (including log lines for rejected requests), channel history/toggle changes, contacts warnings (malformed/unreadable/inaccessible file) and open/create errors, and any errors are logged.
- **One sanctioned exception:** the pre-`setupLogging` messages — config errors (`config error: ...`, E1–E9) and the no-config WARN — are written to raw stderr via `fmt.Fprintln(os.Stderr)` in `main`, because the sink is itself a config product. They must stay outside the `log` package so a `quiet: true` in the file can never hide them.
- `setupLogging(logfile, quiet)` selects the sink: `quiet` → `io.Discard`; `logfile == ""` → console (stderr); otherwise an append-mode file (created, dir auto-created). On GUI/console-less Windows builds the file is the realistic destination.

## Gotchas

- **`systray` (and parts of `beeep`) require cgo — builds must be `CGO_ENABLED=1`.** The Makefile sets this. A cgo build needs the platform C/toolchain + dev headers: Windows → MinGW-w64/MSYS2 gcc; Linux → `gcc` + **GTK 3** + **libayatana-appindicator** dev headers; macOS → system C toolchain.
- **Cross-build reality:** `build-windows` from a non-Windows host needs `CC=x86_64-w64-mingw32-gcc`; `build-darwin` is realistically built on a **macOS host/CI**, not cross-compiled from Linux. Don't claim one-from-all.
- **Config discovery quirks:** (a) under `go run`/`go test`, `os.Executable()` points at an ephemeral toolchain temp dir, so the "next to the executable" candidate is a no-op in the dev flow — `make run` is covered by the CWD and user-config-dir candidates (works for installed binaries); (b) the user-config-dir candidate is a **generic filename in a shared namespace** (`%APPDATA%\config.yml`, `~/.config/config.yml`, `~/Library/Application Support/config.yml`) — another app's `config.yml` there is picked up and drives this app's config: strict decoding (unknown key / wrong type = startup error) is the guard, and an explicit `-config` remains the unambiguous choice.
- **Contacts creation fallback:** when auto-discovery finds no `contacts.csv`, the creation target is **CWD → user-config-dir → exe-dir** — deliberately the reverse of the search order's tail, because under `go run` the exe dir is the same ephemeral toolchain temp dir as above; CWD-first keeps the dev flow (and the created file) usable. The chain is a fallback only when a base dir cannot be **determined** (`Getwd`/`UserConfigDir`/`Executable` errors) — it is **not** a retry on permission failure: a permission-denied creation just errors in `EnsureFile` and is logged. An explicit `-contacts <path>` is used as-is and created on demand by "Edit contacts".
- **Linux runtime:** the tray icon needs a StatusNotifier/app-indicator (DBUS) environment; notifications use a `notify-send` D-Bus session. `beeep.Beep` and `beeep.Notify` are best-effort and may be no-ops in some environments — they must never block the HTTP request.
- **Windows beep quirk:** `beeep.Beep` uses `kernel32.Beep`, which works only in console-subsystem processes. The shipped binary is `-H windowsgui` (no console), so it fails with the bogus "The handle is invalid." (verified standalone). `beep_windows.go` falls back to `user32.MessageBeep` (MB_OK) when `beeep.Beep` returns an error. Console builds (`go run`) beep directly — the fallback simply never fires there. Don't "simplify" the fallback away.
- The server binds `0.0.0.0` by default with **no authentication** (the optional allow-list — `-allowed-ips` flag or YAML `allowed_ips` — is the only access control, and it trusts only `r.RemoteAddr` — clients behind a proxy appear as the proxy's IP). This is an unauthenticated endpoint meant for local/LAN use only — don't expose it to the internet; guard the port at the network level if it must be reachable beyond localhost.
- The handler stays non-blocking: `notify` and `beep` each run in their own goroutine, and the response is written to the phone immediately. Preserve this. (History recording is synchronous and in-memory — it must stay cheap and lock-bounded.)
- The call history is **memory-only** (capacity 20) and deliberately lost on restart. Do **not** persist it (disk, network, or config) — that would break the stateless-everywhere-else design.
- `make` targets use POSIX shell — on Windows run make from Git Bash/MSYS, not raw make-for-Windows, or the `clean` target (`rm -rf`) will fail.
- `go.mod` says `go 1.27` — use a matching local toolchain.
