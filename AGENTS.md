# AGENTS.md

YealinkNotifier is a **cross-platform (Windows / Linux / macOS), small Go app**: an HTTP server that receives Yealink phone "Incoming Call" webhooks and shows a **system notification + beep**, with a **system-tray icon** (status toggle, per-channel toggles, in-memory call history + Exit for graceful shutdown). Go 1.27, module `YealinkNotifier`.

## Layout

- `main.go` — flags, `log` setup, the startup banner, the composition root (wires `core` + `server` + `tray`), the SIGINT/SIGTERM watcher, and the bounded (~5s) shutdown closure.
- `core/` — `App`: two independent channel states (`notify` / `beep`, each `atomic.Bool`; constructor `New(notify, beep)`), `OnCall` (sanitizes the caller, records the event **even if both channels are off**, then dispatches `Notify` and/or `Beep` per enabled channel, each in its own goroutine), `Notify`/`Beep` via `beeep`, and the shutdown orchestration (`Shutdown` is `sync.Once`-deduped, `Done()` closes after the server drain). `history.go` — the in-memory call history: `RecordEvent`/`Events` (defensive copy, newest first)/`ClearHistory`/`HistoryVersion`, `HistoryCapacity` = 20 (memory only, no persistence). `beep_windows.go`/`beep_other.go` — beep fallback on Windows (`MessageBeep` when `beeep.Beep` fails) / passthrough log on other OSes.
- `server/` — the `http.Server` (full timeout set) + the method-agnostic `/` handler (query `number` with `caller` fallback; optional IP allow-list — `New` returns an error on any unparseable entry, the handler checks `r.RemoteAddr` and answers `403 Forbidden`) + bounded `Shutdown`.
- `tray/` — the `systray` menu (top→bottom): master "Disable/Enable notifications" toggle, "Show notifications" checkbox, "Play sound" checkbox, **History** submenu (last 20, newest first; 20 pre-created slot items — stable IDs, no add/remove — shown/hidden per occupancy: `SetTitle` + `Show()` when used, `Hide()` when unused; Windows appends reshown items in call order → keep ascending index iteration), "Clear history", separator, Exit; plus `Stop()`, the headless-safe `RunSafe` wrapper, and the per-OS `trayIconBytes` selector (ICO on Windows, PNG on Linux/macOS).
- `images/` — embedded icons: PNG (`PngOnData` green / `PngOffData` red / `PngIncomingData` for `beeep.Notify`) for the Linux/macOS tray + notifications, ICO (`IcoOnData`/`IcoOffData`) for the Windows tray.
- **Test suite (real now):** `core/app_test.go` (caller sanitization), `core/history_test.go` (capacity, ordering, versioning, concurrency), `core/toggles_test.go` (channel toggles; `OnCall` records with zero side effects), `server/server_test.go` (allow-list parsing/matching, handler accept/deny). Hermetic — no network, no real notifications.
- A small set of packages (`main`, `core`, `server`, `tray`, `images`) with a one-way dependency graph `main → {core, server, tray, images}`; no frameworks, no further abstraction layers. Keep it that way.

## Commands

- Run: `make run` (=`go run .`) or the built binary. Flags: `-port` (default `8080`), `-addr` (default `0.0.0.0`), `-logfile` (default: a file under the OS user-cache dir; empty string = console), `-quiet` (disable logging), `-notify` (default `true` — system-notification channel), `-beep` (default `true` — sound channel), `-allowed-ips` (default empty = allow all; comma-separated client IPs / CIDRs; **any** unparseable entry = startup error, exit 1, before the socket opens), `-version` (print version and exit).
- Verify: `make test` (`go test ./...`) — the repo **has a test suite** covering `core` (sanitize / history / toggles) and `server` (allow-list); hermetic, no network. Plus `make vet` (`go vet ./...`) and a format check — `gofmt -l .` (lists files needing formatting; empty = clean) or `make fmt` (auto-fixes). Run `make test` and `make vet` before declaring a change done.
- Build: `make build` (native) → `bin/YealinkNotifier`; cross-builds `make build-windows` / `make build-linux` / `make build-darwin` → `dist/`. All builds are **`CGO_ENABLED=1`** (see gotchas). Built with `-trimpath -ldflags "-s -w -X main.version=$(VERSION)"`. Binaries in `bin/`/`dist/` are gitignored and pre-existing — never commit or delete them.

## Conventions (do NOT change)

- **Cross-platform is the point.** Do **not** reintroduce platform-specific paths in shared code (`winmm.dll`/`PlaySoundW`, PowerShell, `go-toast`). Notifications+sound go through `github.com/gen2brain/beeep`; the tray goes through `github.com/getlantern/systray`. The **only** sanctioned platform exceptions are the two build-tagged files: `core/beep_windows.go` (Windows `MessageBeep` fallback via `syscall`, see gotchas) and `trayIconBytes` in `tray/tray.go` (ICO vs PNG selection). Add new cross-platform behavior without breaking the win/linux/darwin builds.
- **Tray semantics:** icon = channel state — **green** (per-OS `IcoOnData`/`PngOnData`) when *at least one* channel is on, **red** (`IcoOffData`/`PngOffData`) when both are off; tooltip `YealinkNotifier — notifications ON/OFF`. Menu order (top→bottom): master toggle (click = both channels on → both off, otherwise → both on), "Show notifications" (channel checkbox), "Play sound" (channel checkbox), **History** submenu (last 20, newest first, `HH:MM:SS — <caller>`; 20 pre-created slot items — stable IDs, created once in `onReady` — **shown/hidden per occupancy**: `SetTitle` + `Show()` when occupied, `Hide()` when unused; do **not** switch to lazy creation or dynamic add/remove, systray v1.2.2 has no item-removal API; on Windows re-added items are appended in `Show()` call order → iterate slots in **ascending** index order), "Clear history", separator, **Exit**. When all channels are OFF the server must still answer `200 OK` (allowed clients); only the toast/beep are suppressed.
- **Independent channels:** `-notify` / `-beep` are independent (both default `true`) and map to `core.New(notify, beep)`; `OnCall` dispatches `Notify` and/or `Beep` per enabled channel, each in its own goroutine, and records the event *first* — even when both channels are off. Rejected (403) requests are **not** recorded. Preserve this.
- **IP allow-list:** `-allowed-ips` (default empty = allow all) restricts the webhook by **TCP peer address only** (`r.RemoteAddr` — no `X-Forwarded-For`; behind a proxy the client appears as the proxy's IP). Empty/whitespace entries are skipped; **any** unparseable entry = startup error, exit 1, *before the socket opens* (fail-closed); when set, the startup banner logs the entry count. Denied requests → `403 Forbidden`, body `Forbidden`, logged. Keep it in the server package.
- **Graceful shutdown:** `Exit` / SIGINT / SIGTERM must end the tray loop, drain the HTTP server (bounded, ~5s), and only then let the process exit — the wait is enforced by `tray.RunSafe` blocking on `app.Done()`. `systray.Quit()` is only ever called from background goroutines (signal watcher, Exit item) — **never from the `systray` event-loop (`onExit`)**, because on macOS `systray.Quit()` blocks until the run loop finishes terminating (that is what fires `onExit`), so calling it there deadlocks.
- The tray code must be **headless-safe**: if the tray can't start (no display / no DBUS), recover and continue as a notification-only server rather than crashing.
- **Icons:** the embedded icons in `images/` are the single source. **Windows tray** must use the ICO bytes (`IcoOnData`/`IcoOffData`) — systray's Win32 `LoadImage` only reads `.ico` files (PNG fails silently with the bogus "The operation completed successfully."); **Linux/macOS tray** use the PNG bytes; **`beeep.Notify`** keeps the PNG bytes (the `PngIncomingData` icon; the Windows tray is the only ICO consumer.). Select per-OS via the `trayIconBytes` helper in `tray/tray.go`. Do not add icon tooling.
- User-facing strings, tray labels, and log messages are **English** — keep new strings in English. User-facing (non-log) text is the notification `Incoming call from Yealink` / `Caller number: %s` (fallback when no caller: `You are being called! Check your office phone.`) — preserve it.
- Webhook contract: handle **any HTTP method** on `/`; read query `number` (Yealink sends `$remote_number`), falling back to `caller`; respond `200 OK` with body `OK` (`403 Forbidden` when the allow-list denies). The caller value is sanitized (SIP URI reduced to the number, trailing `_<suffix>` stripped, XML-unsafe chars removed, length capped) before it is used in the notification or recorded in the history — preserve this. Keep it minimal: no auth, no persistence — the call history is intentionally in-memory only (capacity 20, lost on restart); do **not** add disk/network persistence.
- Code comments are in English; match local style.

## Logging

- Route all runtime output through the standard `log` package (never `fmt.Println` for operational messages). The startup banner (including the allowed-entry count when `-allowed-ips` is set), webhook events (including log lines for rejected requests), channel history/toggle changes, and any errors are logged.
- `setupLogging(logfile, quiet)` selects the sink: `quiet` → `io.Discard`; `logfile == ""` → console (stderr); otherwise an append-mode file (created, dir auto-created). On GUI/console-less Windows builds the file is the realistic destination.

## Gotchas

- **`systray` (and parts of `beeep`) require cgo — builds must be `CGO_ENABLED=1`.** The Makefile sets this. A cgo build needs the platform C/toolchain + dev headers: Windows → MinGW-w64/MSYS2 gcc; Linux → `gcc` + **GTK 3** + **libayatana-appindicator** dev headers; macOS → system C toolchain.
- **Cross-build reality:** `build-windows` from a non-Windows host needs `CC=x86_64-w64-mingw32-gcc`; `build-darwin` is realistically built on a **macOS host/CI**, not cross-compiled from Linux. Don't claim one-from-all.
- **Linux runtime:** the tray icon needs a StatusNotifier/app-indicator (DBUS) environment; notifications use a `notify-send` D-Bus session. `beeep.Beep` and `beeep.Notify` are best-effort and may be no-ops in some environments — they must never block the HTTP request.
- **Windows beep quirk:** `beeep.Beep` uses `kernel32.Beep`, which works only in console-subsystem processes. The shipped binary is `-H windowsgui` (no console), so it fails with the bogus "The handle is invalid." (verified standalone). `beep_windows.go` falls back to `user32.MessageBeep` (MB_OK) when `beeep.Beep` returns an error. Console builds (`go run`) beep directly — the fallback simply never fires there. Don't "simplify" the fallback away.
- The server binds `0.0.0.0` by default with **no authentication** (the optional `-allowed-ips` allow-list is the only access control, and it trusts only `r.RemoteAddr` — clients behind a proxy appear as the proxy's IP). This is an unauthenticated endpoint meant for local/LAN use only — don't expose it to the internet; guard the port at the network level if it must be reachable beyond localhost.
- The handler stays non-blocking: `notify` and `beep` each run in their own goroutine, and the response is written to the phone immediately. Preserve this. (History recording is synchronous and in-memory — it must stay cheap and lock-bounded.)
- The call history is **memory-only** (capacity 20) and deliberately lost on restart. Do **not** persist it (disk, network, or config) — that would break the stateless-everywhere-else design.
- `make` targets use POSIX shell — on Windows run make from Git Bash/MSYS, not raw make-for-Windows, or the `clean` target (`rm -rf`) will fail.
- `go.mod` says `go 1.27` — use a matching local toolchain.
